이 단계의 생각

왼쪽에서 i를 밀고, 오른쪽에서 j를 당겨서, 피벗보다 큰 값과 작은 값을 만나게 하면 교환한다. 여기까지는 정확합니다.

문제는 값이 피벗과 같을 때입니다. while arr[i] < pivot은 같은 값 앞에서 멈추고, while arr[j] > pivot도 멈춥니다. 둘 다 제자리에서 같은 자리를 무한히 교환하게 됩니다.

그래서 if arr[i] == arr[j] and i != j: j -= 1이라는 줄을 붙였습니다. 무한 루프는 실제로 멈춥니다. 대신 다른 대가를 치릅니다.

01_quick_sort.py · 분할 부분붉은 줄이 문제의 지점
        def quick_sort_module(arr, start, end):
            i = start
            j = end
            n = (start + end) // 2
            pivot = arr[n]
            while i < j:                        # 검사가 교환보다 앞 회전에 있음
                while arr[i] < pivot:
                    i += 1
                while arr[j] > pivot:
                    j -= 1
                if arr[i] == arr[j] and i != j:  # 무한 루프를 막는 한 줄
                    j -= 1                       # 그 대가로 분할이 1대 n-1이 됨
                arr[i], arr[j] = arr[j], arr[i]
            return j

    def quick_sort_helper(arr, start, end):
        if start >= end:
            return
        i = start - 1
        j = end + 1
        n = (start + end) // 2
        pivot = arr[n]
        while True:
            i += 1
            while arr[i] < pivot:
                i += 1
            j -= 1
            while arr[j] > pivot:
                j -= 1
            if i >= j:
                break
            arr[i], arr[j] = arr[j], arr[i]
        quick_sort_helper(arr, start, j)
        quick_sort_helper(arr, j + 1, end)

    def quick_sort_helper(arr, start, end):
        while start < end:
            n = (start + end) // 2
            if arr[start] > arr[n]:
                arr[start], arr[n] = arr[n], arr[start]
            if arr[start] > arr[end]:
                arr[start], arr[end] = arr[end], arr[start]
            if arr[n] > arr[end]:
                arr[n], arr[end] = arr[end], arr[n]
            # start, n(중앙 인덱스), end를 최소값 - 중앙값 - 최댓값으로 정렬

            i = start - 1
            j = end + 1
            pivot = arr[n]
            while True:
                i += 1
                j -= 1
                while arr[i] < pivot:
                    i += 1
                while arr[j] > pivot:
                    j -= 1
                if i >= j:
                    break
                arr[i], arr[j] = arr[j], arr[i]
            if (j - start + 1) >= end - j:

퀵 정렬의 분할에는 표준 방식이 둘 있습니다. 지금까지 본 세 단계는 모두 호어(Hoare) 분할이고, 다른 하나가 로무토(Lomuto) 분할입니다. 문제 파일의 힌트에 적힌 "피벗 선택 — 일반적으로 마지막 원소"가 바로 로무토를 가리킵니다.

def partition(arr, low, high):
    pivot = arr[high]              # 피벗을 마지막 원소로 고정
    i = low - 1                    # 작은 값들의 경계
    for j in range(low, high):     # 왼쪽에서 오른쪽으로 한 번 훑기
        if arr[j] <= pivot:        # 같은 값도 전부 왼쪽으로
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[high] = arr[high], arr[i + 1]   # 피벗을 제자리에
    return i + 1                   # 경계가 아니라 '피벗의 자리'

def quick_sort_helper(arr, low, high):
    if low < high:
        pivot_index = partition(arr, low, high)
        quick_sort_helper(arr, low, pivot_index - 1)   # 피벗 칸 제외
        quick_sort_helper(arr, pivot_index + 1, high)  # 피벗 칸 제외

피벗을 마지막 원소로 고정했기 때문입니다. 이미 정렬된 배열이면 마지막 원소가 언제나 최댓값입니다. 분할이 매번 n-1 대 0이 되어, 한 층에 원소 하나씩만 떨어져 나갑니다. 그런데 정렬된 입력은 실전에서 가장 흔한 입력 중 하나입니다.

그리고 <=로 비교하기 때문입니다. 피벗과 같은 값을 전부 왼쪽으로 보내니, 원소가 전부 같은 배열에서도 똑같이 무너집니다.

단계 1의 반창고 줄과 증상은 같지만 원인이 다릅니다. 단계 1은 지수가 움직이지 못해서 생긴 문제였고, 이쪽은 피벗을 고르는 방법과 비교 연산자 때문입니다.

문제 파일의 힌트는 로무토를 가리켰지만, 실제로는 가운데 원소를 쓰는 호어 방식을 고른 쪽이 훨씬 견고했습니다. 힌트대로 짰다면 정렬된 입력에서 원소 1,000개만 넘어도 죽는 코드가 나왔을 겁니다. 로무토가 나쁜 방식이라는 뜻은 아닙니다. 피벗을 무작위로 고르거나 세 값의 중앙값을 쓰면 이 약점은 대부분 사라집니다. 마지막 원소로 고정한 것이 약점의 원인입니다.
측정 환경 — CPython 3, WSL2. 정확성은 길이 0~9, 값 0~5인 무작위 배열 3,000개로 각 단계를 검증했습니다. 시간은 원소 20,001개를 각 입력 모양별로 한 차례 실행한 값이며, 재귀 깊이를 측정하기 위해 파이썬 기본 재귀 한도(1000)를 임시로 올렸습니다. 별도로 기본 한도 그대로 실행했을 때, 단계 1은 원소 2,000개의 중복 배열에서 RecursionError로 실패했고 단계 2와 3은 통과했습니다. 부록의 로무토 방식은 같은 조건에서 원소 1,000개의 정렬된 배열부터 실패했습니다. 부록에서 비교한 ANSWER_01_quick_sort.py는 표준 정답본이 아니라 대조용으로 작성된 또 하나의 구현입니다.
