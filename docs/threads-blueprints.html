쓰레드 도면집

프로세스는 방 한 칸, 쓰레드는 그 방에서 일하는 일꾼이에요. 오늘 나눈 이야기를 그림 여섯 장으로 정리했어요.

프로세스, 각자의 방

도면 01
프로세스는 저마다 독립된 방(가상메모리)을 가져요. 옆방 물건은 절대 못 봐요.

방 안의 층별 배치도

도면 02
아래부터 코드 → 데이터 → 힙 → 공유 라이브러리 → 스택 → 커널 순으로 쌓여 있어요. 힙은 위로, 스택은 아래로 자라며 서로 마주봐요.

같은 방을 쓰는 일꾼들

도면 03
쓰레드는 책상(코드·힙·데이터)은 같이 쓰고, 서랍(스택)만 따로 가져요. 그래서 서로 간섭이 가능해요.

조명이 방을 오가요

도면 04
A가 디스크를 기다리는 동안, CPU 조명이 B로 넘어가요. 컨텍스트 스위칭이 노는 시간을 채워줘요.

코어 1개 vs 코어 2개

도면 05
코어 하나는 번갈아가며 일하고, 코어 둘은 진짜 동시에 일해요. 오라버니 컴퓨터는 코어가 여럿이라 실습에서 진짜 충돌이 났어요.

동시에 만지면 사라져요

도면 06
기대한 값 200000 중에서 실제로는 100000만 남았어요. 두 손이 동시에 같은 물건을 고치다가 한쪽 결과가 지워진 것, 이게 실습에서 본 race condition이에요.

한눈에 보는 대응표

  • 프로세스 = 독립된 방 하나
  • 가상메모리 = 방 안의 층별 배치도
  • 쓰레드 = 방을 같이 쓰는 일꾼
  • 스택 = 일꾼 개인 서랍
  • 컨텍스트 스위칭 = 방을 오가는 조명
  • 코어 = 실제 조명 개수
  • race condition = 동시에 만져서 사라진 결과
